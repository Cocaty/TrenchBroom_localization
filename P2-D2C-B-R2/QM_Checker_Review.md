日期：2026-11-16 ｜ 逐脚本审查：比较逻辑是否只取前 16 字节、结果有效性、影响范围

## 一、逐脚本审查

### 1. P2-D2B-R1 检查脚本（26 字节 QM）
- **逻辑**：`magic = bytes([...0xa7])`（17 字节定义）；比较 `qm[:16] == magic[:16]`
- **实际语义**：`magic[:16]` = `3cb8…bdd` = **恰好等于标准 16 字节魔数** → 该比较实质上是有效的 16 字节比较
- **结果 True 的有效性**：✅ **成立**（26B QM 前 16 字节实测等于标准魔数）
- **表述缺陷**：报告把魔数称为"17 字节标准"——**术语错误**（正确：16 字节标准 + 0xa7 为 Language 块标签）
- **结论影响**：结论保留，表述修正

### 2. P2-D2C-B 脚本（366 字节 QM）
- **逻辑**：`magic` 仍为 17 字节定义；比较 `qm[:16] == magic`（**未切片**）→ 16 字节与 17 字节比较，**恒为 False**
- **结果 False 的有效性**：❌ **无效结果**——修正比较（前 16 字节 vs 标准 16 字节）后为 **True**
- **结论影响**："魔数匹配 False" 撤回；"QM 嵌入/有效"结论不依赖该行（依赖 UTF-16 内容命中），**仍然成立**

### 3. P2-D2C-B-R1 `Evidence/qm_exe_check.py`
- **逻辑**：17 字节定义 + `qm[:17] == magic`（17 字节全等比较）
- **结果 True 的有效性**：⚠️ **形式上有效但判据错误**——文件前 17 字节 = 16 字节魔数 + 0xa7（Language 块标签首个字节），把**块标签字节计入了魔数**（违反本轮规则 8）
- **正确判据**：`qm[:16] == 标准魔数` → 同样为 True（本轮 qm_checker_16.py 实测）
- **结论影响**：结论保留，判据修正；R1 报告中"17 字节标准魔数"表述撤回
- **影响范围**：仅"魔数"一词的表述与该单一比较行；**不影响** R1 的 UTF-16 译文命中、资源名命中、TS 对账、Git 完整性等任何其他结论
